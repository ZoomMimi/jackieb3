Create `scripts/10-upload-r2.mjs` — an ESM Node script that, per in-scope voyage day, exports that day's exact photo UUIDs from the Photos library, resizes them, uploads them to Cloudflare R2, and rewrites the post's Gallery array with the resulting public URLs.

Imports: `readFileSync, writeFileSync, readdirSync, mkdirSync, rmSync, existsSync, statSync` from `node:fs`; `join, basename, extname, dirname` from `node:path`; `fileURLToPath` from `node:url`; `execFileSync` from `node:child_process`; `tmpdir` from `node:os`; `sharp` from `sharp`; `{ S3Client, PutObjectCommand }` from `@aws-sdk/client-s3`.

Constants: `ROOT`, `DATA_DIR` (`.planning/data`), `POSTS_DIR` (`src/content/blog/great-loop`), `STAGING = join(tmpdir(), 'jackieb3-r2-staging')`, `DERIVATIVES_ROOT = join(process.env.HOME, 'Pictures/Photos Library.photoslibrary/resources/derivatives')`, and the two in-scope `RANGES` (2024-04-13..2024-05-17, 2023-06-05..2023-08-31).

CLI flags: `--dry-run`; `--date YYYY-MM-DD` (repeatable, restricts the run to those dates); `--limit N` (process at most N posts this run); `--force` (ignore the `r2Uploaded` idempotency gate); `--allow-derivative-fallback` (see step 4). Print the effective flag set at startup.

Credential guard — mirror `getClient()` from scripts/07-quality-lift.mjs exactly in shape: a lazy `getR2Client()` holding a module-level `_r2Client`, which on first call checks `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PUBLIC_BASE` and, for any missing one, prints an error naming the variable plus the hint "set it in .env (already gitignored) or export it, then run: npm run upload-r2", and calls `process.exit(1)`. It then constructs `new S3Client({ region: 'auto', endpoint: 'https://' + R2_ACCOUNT_ID + '.r2.cloudflarestorage.com', credentials: { accessKeyId, secretAccessKey } })`. It must be lazy so `--dry-run` works with no credentials set at all. Never log credential values anywhere, including error paths.

Copy `splitFrontmatter`, `parseFrontmatter`, and `serializeFrontmatter` verbatim from scripts/04-generate-stubs.mjs. This project duplicates that trio per-script rather than sharing a module; follow that convention, do not create a shared utils file.

Per-run flow:
1. Build the in-scope date set from the keys of `src/data/daily-routes.json` that fall inside either range. Then list `.mdx` files in POSTS_DIR whose first 10 filename characters are in that set. Apply `--date` and `--limit` filters. Sort by date ascending so runs are deterministic and resumable.
2. For each post: split/parse frontmatter. Skip with `SKIP <slug> (already uploaded)` when `fm.r2Uploaded === true` and `--force` is absent. Extract the Gallery array by matching the `<Gallery images={[ ... ]} />` block and collecting every double-quoted `file://` entry, preserving order. For each entry derive `uuid = basename(path, extname(path))` and `isVideo = extname(path).toLowerCase() === '.mov'`. If a post has no Gallery block or zero entries, log it, count it as skipped, and move on without modifying the file.
3. Export: write the post's UUIDs one-per-line to `<STAGING>/<date>/uuids.txt`, then invoke osxphotos via `execFileSync('osxphotos', [...])` using the ARRAY-ARGS form (never a shell string — 06-PATTERNS.md flags shell-injection risk with UUID lists). Arguments: `export`, `<STAGING>/<date>`, `--uuid-from-file`, `<uuidsFile>`, `--convert-to-jpeg`, `--jpeg-quality`, `1.0`, `--jpeg-ext`, `jpg`, `--filename`, `{uuid}`, `--skip-live`, `--download-missing`, `--use-photokit`, `--retry`, `2`, `--report`, `<STAGING>/<date>/export.csv`. `--filename {uuid}` makes the exported filename deterministic (`<UUID>.jpg` for images, `<UUID>.mov` for videos). `--convert-to-jpeg` performs HEIC decoding using macOS's native decoder — sharp CANNOT decode HEIC (06-RESEARCH.md Pitfall 1, confirmed: this machine's sharp lists only `.avif` under `format.heif.input.fileSuffix`), so this step is mandatory and must run before any sharp call. `--download-missing --use-photokit` is required because 99.6% of in-scope originals are iCloud-only on this machine. Give execFileSync a generous `timeout` (at least 30 minutes) and `maxBuffer` (at least 32 MB) since iCloud downloads are slow.
4. Locate each expected export: `<STAGING>/<date>/<UUID>.jpg` for images, `<STAGING>/<date>/<UUID>.mov` for videos. If an image's expected file is absent AND `--allow-derivative-fallback` was passed, fall back to `<DERIVATIVES_ROOT>/<UUID[0]>/<UUID>_1_105_c.jpeg` (a cached 1022x768 JPEG) and record the uuid in the post's `derivativeFallbacks` list. Without the flag, or for a missing video (videos have no derivative fallback), record the uuid in `missingExports` and fail the whole post.
5. Resize images only: `sharp(input).resize({ width: 1600, withoutEnlargement: true }).jpeg({ quality: 80 }).toFile(<STAGING>/<date>/resized/<UUID>.jpg)`. `withoutEnlargement: true` prevents upscaling photos already narrower than 1600px. Videos are uploaded byte-for-byte as exported — there is no video transcoding step (D-02; ffmpeg is not installed and is out of scope).
6. Upload every one of the post's media files with `PutObjectCommand`: `Bucket` = `R2_BUCKET`, `Key` = `great-loop/<date>/<UUID>.jpg` or `great-loop/<date>/<UUID>.mov`, `Body` = the file buffer, `ContentType` = `image/jpeg` or `video/quicktime`. Accumulate uploaded byte totals.
7. Commit all-or-nothing (06-RESEARCH.md Pitfall 4): only after every one of the post's media files has uploaded successfully, rebuild the Gallery array preserving the original entry order with `<R2_PUBLIC_BASE>/great-loop/<date>/<UUID>.<jpg|mov>` (strip any trailing slash from R2_PUBLIC_BASE first), set `fm.r2Uploaded = true`, and write the file back as `'---\n' + serializeFrontmatter(fm) + '\n---\n\n' + newBody + '\n'`. On ANY error at any step, log `FAIL <slug>: <message>`, push `{ slug, error }` to the failed list, and leave the MDX file completely unmodified so the `file://` entries survive for a clean retry.
8. Remove `<STAGING>/<date>` after a post commits successfully; leave it in place on failure for inspection.
9. Write `.planning/data/r2-upload-report.json` with `{ generated, durationSeconds, summary: { total, processed, skipped, failed, filesUploaded, bytesUploaded, derivativeFallbackCount }, processed, skipped, failed, derivativeFallbacks, cumulative: { postsWithR2Uploaded } }`, following the report shape in scripts/07-quality-lift.mjs. `cumulative.postsWithR2Uploaded` is computed by rescanning all in-scope posts' frontmatter at the end of the run, so batched runs report true overall progress. The report must never contain credential values.

`--dry-run` behavior: perform steps 1-2 only, print one `WOULD UPLOAD <slug> (<n> images, <m> videos)` line per post plus a run total, never call `getR2Client()`, never invoke osxphotos or sharp, and exit 0.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local script -> Cloudflare R2 | Long-lived write credentials cross this boundary on every upload |
| local Photos library -> public internet | Anything exported and uploaded becomes world-readable, permanently |
| shell -> osxphotos CLI | UUID lists are passed as process arguments |
