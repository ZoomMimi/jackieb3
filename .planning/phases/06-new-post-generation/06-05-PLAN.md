## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local Photos library -> public R2 bucket | ~1813 media files cross into world-readable storage in this plan |
| R2 bucket -> public internet | Every uploaded object is permanently fetchable by anyone with the URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Information Disclosure | Bulk `osxphotos export` of ~1813 files to a public bucket | mitigate | Every export is `--uuid-from-file` scoped to the UUIDs already listed in that specific post's Gallery array, which were curated per-day by `scripts/03-correlate.mjs`. No date-range, album, or whole-library export path exists in `scripts/10-upload-r2.mjs` (asserted in plan 06-02's acceptance criteria). `--skip-live` prevents live-photo video components from being pulled in as unexpected extra objects |
| T-06-01 | Information Disclosure | R2 credentials during a long batched run | mitigate | Credentials come from `.env` via `--env-file-if-exists` and `process.env` only; `r2-upload-report.json` is asserted to contain no credential values; failures log error names, not request signing material |
| T-06-11 | Tampering | Partial Gallery rewrite during a batch interruption | mitigate | All-or-nothing per-post commit means an interrupted post keeps its `file://` entries and no `r2Uploaded` flag. Each task requires a `git diff` cleanliness check on any failed post before retrying, and Task 3's phase-wide gate would catch any mixed-state file as `FILE_URL_POSTS > 0` |
| T-06-12 | Denial of Service | Exceeding the R2 free tier (10 GB storage / 1M Class A writes per month) | mitigate | ~1846 PUT operations is far under the 1M Class A monthly limit. Storage is tracked cumulatively in the report, with an explicit stop-and-report threshold at 7 GB so an unexpected blowup (most plausibly video volume) forces a decision instead of silently incurring cost |
| T-06-06 | Denial of Service | `r2.dev` public URL rate limiting | accept | Previously accepted in plan 06-02; the verification sampling here is 25 requests total, nowhere near any documented limit |
</threat_model>
