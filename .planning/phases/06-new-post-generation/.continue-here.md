## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Assuming a UI "state reset" bug is JS logic | The photo-strip scroll-position bug looked like a JS state bug (fixed once in `1fb144f` by saving/restoring `scrollLeft`) but the real cause was CSS: `.photo-card img` had no fixed `width`, so its layout size was unknown until the (cache-busted, always-refetched) image finished loading over the network — at the moment `scrollLeft` was restored, the strip's scrollable width was still ~0 and got clamped back to 0 regardless of the saved value. | advisory | Before patching JS state to fix a layout-reset symptom in `narrative-viewer.mjs`, check whether the affected elements have fixed CSS dimensions. If a box's size depends on async content (an image, a video, fetched data), give it an explicit width/height so layout is deterministic the instant it's inserted. Real fix: `d6e3606`. |
