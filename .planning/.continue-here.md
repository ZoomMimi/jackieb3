## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Bulk regex-removing a component tag from many MDX files without checking what it leaves adjacent | Removing `<VoyageStats .../>` from all 361 post bodies silently broke MDX compilation in 224 of them by collapsing the blank line MDX requires between a trailing `import` block and the following JSX (e.g. `<Gallery images={[...`). The build error ("15:1: Unexpected statement... only import/exports are supported") gave no filename at all — rolldown/mdxjs-rs bundles many files together, so per-file errors don't surface a path. | advisory | Found via binary-search bisection: repeatedly moving half the candidate files out to a scratch dir and rebuilding until the single failing file was isolated (`python3` loop, ~9 iterations). If a future bulk MDX edit breaks the build with no filename in the error, use this bisection approach immediately rather than grep-guessing — it's much faster. Also: after any bulk removal of a tag, explicitly re-check that a blank line still separates the last `import` line from the first following content line. |
